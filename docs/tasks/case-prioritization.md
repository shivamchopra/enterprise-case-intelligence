## Delivered domain, persistence and API

- Domain priority rules, Normal creation default, validated Closed same-value no-op versus differing-value conflict; status progression remains independent.
- Authorized `GET /cases/{id}/priority`, CSRF-protected Caseworker `PUT`, exact two-field representations and strict input/query/media/error behavior. Optional exact `priority` list filter combines with title/status/boundary before ordering/Take. Summary remains the existing status aggregate.
- `StoredPriority` and Fluent API primary/foreign key, restrictive deletion, value check and STRICT table, scaffolded `AddCasePriority` migration/designer/snapshot. A column/check candidate was scaffolded and removed after its actual SQLite rebuild emitted transaction-suppressed foreign-key commands. The selected migration is a single transactional CreateTable and preserves existing table catalogs.
- Explicit two-migration chain with bounded metadata and per-migration EF patch checks, historical initial target-model schema validation, format-5 no-overwrite initialization and direct offline 1/2/3/4 → 5 upgrades. Validate sources before mutation; create missing legacy tables/baselines only when required; bounded tracked Normal backfill; validate target before committing metadata/marker together. No startup migration, reset or automatic retry.
- Atomic case/priority/history/key creation, tracked priority changes and commit-before-success. Restore/selected reads/list lookahead/status changes/replay/deep inspection reject encountered missing/invalid priority. Left joins preserve missing-dependent detection. No ordinary operation supplies a repair default. Priority is current state without actor/time/history evidence.

## Delivered workspace

The All/Low/Normal/High filter combines with submitted title/status before paging. Next and refresh retain filters, while filter changes start at the first page. Lookup preserves the list; priority loads only for the selected case, without list-row fetches or badges. Overall status totals remain independent.

The selected priority has its own bounded read, loading/error/refresh state, exact response/identity validation and generation checks. Reader sees the current value. Caseworker editing requires both current case/status and priority loaded successfully for the latest selection. A failed case/priority read hides editing without inventing Normal. Closed has no differing action. The native selector and explicit Save work by keyboard, with labels, visible focus, live feedback and narrow/zoomed layouts.

Pending status/priority writes block duplicate and competing actions across selection changes. Confirmed priority writes refresh selected details/history/priority, the first filtered page and independent status totals; failed follow-up reads do not erase the confirmation. Failure/uncertainty invalidates both current case and priority plus outstanding reads before another explicit action. Refresh priority can recover its value independently, but cannot make unavailable case status editable. An old-session write settling after access refresh also invalidates the same reselected case without presenting old feedback. No mutation replays automatically.

The new published browser coverage exercises these boundaries with actual retained data, committed-response loss, failed/late reads, concurrent Close, blocking of competing priority/status actions, denial after a committed priority change, and the original frozen creation key/payload replay after reprioritization and Closed. Real OIDC browser journeys exercise Reader/Caseworker controls and actual CSRF-protected priority writes through direct/proxy HTTPS with both certificate sources. Sign-out, expiry/deadline, access refresh and 401/403 clear current priority/choice and reject prior-session responses. Workspace addresses/storage stay free of case priority/text/IDs and retry keys; normal API request values remain observable to HTTP infrastructure.

The browser delivery changes no model/migration/provider, runtime dependency or store format beyond the already implemented format 5. The backend compatibility/failure evidence above remains required regression coverage. Screenshot artifacts use disposable synthetic cases and test identities only.

No new cloud resource, provider registration, billing/credit use, server database, ownership, priority sorting, SLA or actor audit is authorized or implemented by this work. The [$0 hosting boundary](zero-cost-review-hosting.md) remains in force.
