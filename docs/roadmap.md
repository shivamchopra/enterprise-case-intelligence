# Project roadmap and priority assessment

The next release is a **local reference application**. A reviewer should be able to clone a tagged version, complete one synthetic case, verify the resulting records and reproduce the documented recovery procedure. An **invited hosted review** has its own acceptance criteria and depends on sustainable $0 out-of-pocket hosting. The local release can proceed while cloud eligibility is unresolved.

## Ordered direction

### 1. Finish the local reference release

A clean-checkout rehearsal on [`871c6bd`](https://github.com/shivamchopra/enterprise-case-intelligence/commit/871c6bd) passed in Chromium using SDK 10.0.404. The closing history entry, brief and receipt agreed on the closure time. The second pull added zero receipts and kept checkpoint `"1"`. Repeat this check and the restore rehearsal on the commit chosen for the tag.

### 2. Prepare for invited review without cloud resources

1. **Exercise a published build with five simultaneous synthetic clients.** Use independent sessions to mix Reader lookups with Caseworker writes. Verify denied Reader writes, retained creation-key replay, final priority and recorded status transitions after contention. Keep receipt verification in the separate LocalDemo walkthrough. Record workload, outcomes and any limits found. The hosted design must later repeat the workload against its real provider and ingress. [Hosted acceptance criteria](requirements/phase-8-secure-hosting.md)
2. **Complete the remaining private identity checks.** Use a separate regular unassigned identity to verify denial, allow a real ticket to reach its 30-minute absolute expiry and exercise a controlled provider failure or misconfiguration. Record only redacted outcomes. Hosted callback, credential rotation and ingress checks depend on an actual environment. [Private Entra checklist and outstanding checks](usage/entra-review-verification.md)

### 3. Establish a sustainable hosted path

Each row depends on the evidence in the preceding row. The November 12 private checks left exact Linux F1 allocation and active spending protection unresolved. Azure App Service F1 and the Azure SQL free tier are assessment candidates. Retain local-only review if the cost or platform requirements cannot be met. [Evidence refresh](tasks/review-hosting-evidence-refresh.md) · [Cost decision](adr/0012-gate-cloud-hosting-on-zero-recurring-cost.md)

## Deferred work

- **External integration.** The current handoff ends at a local receipt. Choose an external consumer, delivery guarantees and service identity when a downstream workflow calls for them. [Closure handoff boundaries](requirements/phase-10-case-closure-handoff.md)
- **Case ownership and tenant isolation.** The proposed hosted review uses a single shared workspace. Different access boundaries need a concrete user scenario and explicit authorization rules. [Hosted scope](requirements/phase-8-secure-hosting.md)
- **Model-backed assistance.** Keep the explicit closure-brief request. The tested local model accepted 12 of 14 unsupported requests. A future candidate must meet the existing offline routing, citation and abstention criteria on synthetic fixtures. [Routing experiment](tasks/closure-brief-routing-experiment.md)

Keep release claims tied to a reproducible check. Add new persistence work when a workflow or operating constraint calls for it, following the repository's EF Core Code First guidance. [Repository instructions](../AGENTS.md) · [Architecture decisions](adr/README.md)
