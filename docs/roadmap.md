# Project roadmap and priority assessment

**Current baseline.** The local browser and API support authenticated case work, title search, priority triage and explicit EF Core Code First format-6 storage. The local closure producer and separate receipt consumer are available. The selected case has a read-only cited closure brief with an offline synthetic evaluation. Hosted acceptance is pending.

## Assessment

The project aims to demonstrate credible enterprise modernization through runnable .NET code, useful workflows, explicit tradeoffs and evidence. Persistence now has durable writes, retained history, retry-safe creation, explicit upgrades and substantial failure/recovery coverage. EF adoption is complete. Further storage work should serve a product or operating requirement.

The Phase 6 priority was the user journey: a reviewer previously needed curl and multiple commands to perform a simple service-desk task. The local browser workspace now connects the existing capabilities without inventing more domain rules or infrastructure. This scenario remains a synthetic reference-project assumption, not validated enterprise research.

| Area | Current evidence / gap | Priority implication |
| --- | --- | --- |
| Case workflow | Find cases by literal title/status, create, retrieve, progress and inspect history through HTTP and the browser workspace. | Case finding delivers the first business enhancement; revisit additional rules when a concrete scenario needs them. |
| User experience | The same-host workspace and command-line walkthrough demonstrate the journey. | Maintain browser/recovery coverage as business behavior evolves. |
| Data and reliability | EF Code First, retained SQLite state, atomic history/key writes and recovery tests are implemented. | Maintain these guarantees during features; avoid making storage hardening the default backlog. |
| Security and hosting | OIDC/cookie, role policies, CSRF and same-host proxy tests, plus private local Entra role/revocation evidence; no hosted deployment; one process/file. [Phase 8 requirements](requirements/phase-8-secure-hosting.md) propose invited shared-workspace access. | Next, assess a compatible zero-recurring-cost platform/storage/ingress, then finish hosted provider/user checks; hosting remains unimplemented. |
| Operations | Liveness and offline inspection exist; readiness, hosted diagnostics and backup/restore are proposed, not implemented. | Select compatible hosting/storage and prove operating/recovery requirements before inviting users. |
| Integration and AI | Local closure notices feed a separate receipt process. Synthetic closure briefs have an offline evaluator. External integration and model-backed assistance remain open. | Retain the explicit closure brief request after the local model failed the unsupported-request gate. |

## Current local delivery

Free-host eligibility remains unconfirmed, so deployment stays on hold under the $0 boundary. Continue useful local product work rather than changing billing, requesting quotas or converting providers speculatively. The [known-ID lookup slice](tasks/open-case-by-id.md) now lets a Reader/Caseworker open current details/history without locating a title or traversing pages. It reuses existing authorized reads and preserves the filtered list and uncertain creation retry state. The [workload overview](tasks/case-workload-overview.md) also gives Readers/Caseworkers overall New/InReview/Closed/total counts through a bounded aggregate, separate from list filters. No cloud mutation or persistence change accompanies these local slices. The current local business slice is [case prioritization](requirements/phase-9-case-prioritization.md): explicit Low/Normal/High choices, filtering and selected-case editing while preserving current case responses/replay. Its Domain/store/API/filter, format-5 lifecycle and browser read/edit/reconciliation workflow are implemented; the [delivery task](tasks/case-prioritization.md) maps the acceptance evidence. Resume hosting acceptance when eligible allocation and the complete cost/security evidence are available.

## Ordered direction

1. **Completed: local browser case workspace.** Browse/filter → create → review details/history → progress status against retained local data. One application host and the existing API, domain and storage contracts remain. [Phase 6 coverage](requirements/phase-6-case-workspace.md#current-implementation-coverage) links real-browser tests and the reproducible local walkthrough.
2. **Completed: focused business enhancement.** [Phase 7 title search](requirements/phase-7-case-title-search.md#current-implementation-coverage) lets staff find known synthetic work without traversing every page. [Case prioritization](requirements/phase-9-case-prioritization.md) now has implemented domain rules, API, explicit retained-store upgrades and browser priority filtering/editing; ownership remains a later candidate. Use EF Code First migrations if a selected later capability changes persisted data.
3. **Next milestone — proposed, not implemented: secure review hosting.** [Phase 8 requirements](requirements/phase-8-secure-hosting.md) define invited Reader/Caseworker access to one shared synthetic workspace, browser/API session and CSRF behavior, ingress/configuration boundaries and proposed recovery targets. [ADR 0009](adr/0009-authenticate-the-shared-case-workspace.md) and the [identity runbook](usage/authenticated-case-workspace.md) now supply the locally testable authenticated slice. [ADR 0010](adr/0010-trust-a-single-loopback-https-proxy.md) now adds tested same-host proxy support. The [hosting assessment](tasks/review-hosting-preparation.md) records the conditional VM/local-file option, and [ADR 0011](adr/0011-use-entra-for-private-review-identity.md) selects Entra with [private local role/revocation evidence](usage/entra-review-verification.md#local-verification-on-2026-10-26). [ADR 0012](adr/0012-gate-cloud-hosting-on-zero-recurring-cost.md) now keeps review local while [zero-cost App Service F1/SQL compatibility](tasks/zero-cost-review-hosting.md) is assessed. The [compatibility assessment and catalog checker](tasks/app-service-compatibility.md) now identify concrete ingress, storage and protection-key gaps. [ADR 0013](adr/0013-load-protection-certificates-from-private-configuration.md) now verifies configuration-backed certificates and retained-key compatibility locally. The [managed-ingress verification contract/probe envelope](tasks/managed-ingress-verification.md) now defines the acceptance evidence. The [independent operator probe](usage/operator-review-probe.md) now verifies local access/retention through real child processes and a copied artifact path. The [2026-10-29 deployment-path assessment](tasks/free-tier-deployment-preflight.md) identifies unresolved storage-isolation and explicit bootstrap contracts; private reads did not establish eligible allocation. The [explicit preparation sequence](usage/operator-review-probe.md#explicit-preparation-and-initialization) now resolves the local initialization dependency while retaining storage checks and requiring read-only old-receipt evidence. The [preparation-only proposal](tasks/preparation-only-deployment-proposal.md) now fixes initial startup and defines release/removal boundaries; refreshed private reads still do not establish eligible allocation. Resolve exact private eligibility/policy evidence before creation review, then prove actual storage/isolation, managed-ingress and cloud credential delivery/retention, then provider compatibility, operations and hosted identity checks, revisiting [readiness](requirements/phase-6-storage-readiness.md) against that actual design. Azure/server-managed storage remain candidates; current SQLite evidence does not establish network-share, ephemeral or multi-instance support. No compute resources or public deployment are selected by the proposal.
4. **Completed: local case closure handoff.** The producer commits a notice with the case closure. The separate intake command applies one bounded page and resumes from its durable checkpoint. Process tests cover interruption, and concurrent attempts exercise exact redelivery. [Two-file demo](usage/local-records-intake.md). [Phase 10 contract](requirements/phase-10-case-closure-handoff.md) · [ADR 0017](adr/0017-use-a-transactional-closure-feed.md)
5. **Completed: local closure brief.** Reader and Caseworker can explicitly request a cited brief for the selected case. The offline evaluation scores facts, citations and abstention. The local routing experiment recognized paraphrases but accepted unsupported requests. [Phase 11 contract](requirements/phase-11-closure-brief-evaluation.md) · [Routing results](tasks/closure-brief-routing-experiment.md)

This ordering can change when a concrete dependency or user need appears. Identity and access boundaries must precede any feature that depends on identifying staff; they cannot be postponed merely to follow the list. Each milestone needs its own requirements and proportionate architecture decisions. No empty projects, speculative services or technology demonstrations are required to fill the roadmap.

## Working rule

Choose the next slice by user outcome, demonstration value and actual dependencies. Maintain tests and public documentation as behavior ships. EF Core Code First is the persistence implementation preference, not a product roadmap. Keep future capabilities separate from current evidence in the README and profile.
