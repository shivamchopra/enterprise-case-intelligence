# Repository instructions

Follow [CONTRIBUTING.md](CONTRIBUTING.md) for quality gates and public-repository guidance.

## Persistence: EF Core Code First

The repository owner's preferred persistence approach is **Entity Framework Core Code First**. Apply this to new persistence work and to the planned conversion of the existing store.

- Define the database model in C# with entities, a `DbContext` and Fluent API configuration. Keep Domain independent of EF Core and database-provider dependencies.
- Use EF Core LINQ queries and tracked changes/`SaveChanges` for ordinary database operations wherever supported. Preserve bounded database queries rather than materializing whole tables for client-side filtering.
- Use EF Core migrations and their checked-in model snapshot for initialization and schema evolution. Scaffold migrations from model changes, inspect the generated operations and test them against the real provider. Do not maintain a parallel hand-written schema/upgrade script for behavior EF can generate.
- SQL generated by EF Core is expected. Hand-written SQL is an exception for a concrete provider limitation, integrity/diagnostic command, historical compatibility bridge or test-only corruption/failure fixture. Use it only where an EF API or migration operation cannot preserve the required behavior; keep it minimal and parameterize runtime values. Explain the limitation and supporting test in the code/ADR and PR. A check-constraint expression configured through Fluent API can remain provider-specific SQL where required.
- Preserve explicit offline initialization/upgrade, no-overwrite setup, validation before I/O, commit-before-success, atomic case/history/key writes and retained-key replay. Do not introduce automatic startup migrations, reset storage or weaken compatibility to simplify EF adoption.
- Give each operation/request an appropriate `DbContext` lifetime; never share one context across concurrent operations. Preserve serialization and transaction semantics required by the current local workflow.

Current runtime code uses EF Core Code First. [The completed adoption task](docs/tasks/ef-core-code-first-adoption.md) and [ADR 0007](docs/adr/0007-adopt-ef-core-code-first.md) document format 4, validated legacy baselines and the remaining provider-specific SQL exceptions. Preserve historical ADRs and frozen legacy fixtures; document the compatibility amendment when implementing the conversion.

## Scope and documentation

Keep the .NET 10 baseline, synthetic-data rule and current application boundaries. Add layers or infrastructure only when concrete implementation needs justify them. Keep implemented and planned scope distinct in the README, architecture and task documents, and update them when behavior changes.
